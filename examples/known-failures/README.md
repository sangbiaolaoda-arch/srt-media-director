# 已知失败案例与局限

> 展示失败比展示最好的一段更可信。本文件记录**真实存在**的失败模式、
> 触发条件与当前处理方式。每条都指向对应的门禁编号，或明确标注「未覆盖」。

---

## F01 · SRT 解析对「缺少空行分隔」极其敏感

**现象**：若 SRT 条目之间没有空行（`cue` 与 `cue` 直接粘连），解析器会把
整份字幕吞成 **1 条 cue**，后续分拍只得到 1 拍，画面退化为单镜头。

**复现**：
```bash
# 去掉条目间空行后解析
python3 - <<'PY'
import sys; sys.path.insert(0,'runtime')
import srt_parser
a = srt_parser.analyze('examples/showcase/03-data-comparison/case.srt')
print('cues =', len(a['cues']))   # 正常应为 20
PY
```

**当前处理**：`srt_parser.analyze()` 返回 `errors` 列表，粘连带会被记为空行
缺失告警，但**不会**阻断。属于「未覆盖」——建议后续加 `SRT-SHAPE` 门禁：
条目数突降或平均时长异常时报警。

**为什么保留**：解析器选择「宽容优先」，是为了不因个别格式瑕疵直接失败；
代价就是这种静默退化。这是明确的取舍，不是 bug 未修。

## F02 · 同质内容会合并、而不是被判为「重复」

**现象**：给一段 8 句高度雷同的字幕（「今天我们讲第 N 个要点」），流水线
把 8 句合并成 **2 拍**，REP 重复感门禁给 **PASS**（`template_run=1`）。

**含义**：门禁**不会误报**——它测的是跨拍构图的重复，不是文本的重复。
但这也意味着：如果内容本身缺乏变化，画面同样缺乏变化，而门禁不会拦。
**门禁保证的是「不无故重复」，不是「强行制造差异」。**

**触发命令**：
```bash
python3 - <<'PY'
import sys; sys.path.insert(0,'runtime')
import pipeline, rep_metrics, json
# 见 tests/known-failures/ 下的 stress 用例
PY
```

**状态**：设计取舍，非缺陷。如需「内容同质也要提示」，应新增文本层指标
（n-gram 重复率），当前未实现。

## F03 · 跨进程可复现性曾经不成立（已修复并有回归测试）

**现象**：黄金回归测试建立后立刻抓到 `beat-plan.json` 在两个独立进程间
哈希不一致。根因是 `semantic_grouper` 的蝉联检测用
`sorted(strong, key=len)[-1]` 取锚点，长度并列时依赖 **集合迭代顺序**，
而它受 `PYTHONHASHSEED` 随机化影响。

**修复**：改为 `sorted(strong, key=lambda g: (len(g), g))[-1]`，长度并列时
再按字典序，彻底消除进程间漂移。

**回归支撑**：`tests/golden/` 固定 SRT + 五层产物归一化哈希比对，
跨进程稳定。这条修复正是「声称可复现就该有测试」的直接产物。

## F04 · 尚无 CJK 排版门禁（未覆盖）

项目以中文字幕为主场景，但下列 CJK 排版风险**目前没有机器门禁**：

- 标点避头尾（行首不得出现 `，。、？！`，行尾不得出现 `（【《`）
- 中英混排间距与断行
- 字体回退链（Noto Serif CJK → Source Han Serif → serif）
- 字体授权登记（OFL）

**状态**：未覆盖。样例库已包含长句与中英混排文案，用于暴露问题，但门禁
（`TYPO-01`）尚未实现。

## F05 · 构图模板覆盖不全（未覆盖）

当前 6 套模板覆盖：单一主体、对比、因果链、前后变化、枚举。
**未覆盖**：层级、时间线、循环、分类、递进强化、让步转折、问答专用构图。

**含义**：当内容属于这些关系类型时，会退化为最接近的现有模板，画面
「能放得下，但不一定最贴切」。

**状态**：未覆盖。补齐顺序见 `ROADMAP.md`。

## F06 · 镜头运动仅 1 种

参考 Runtime 只实现了 1 种镜头运动。跨拍转场依赖 dissolve + carry_over，
尚无完整转场语法库。

**状态**：未覆盖，属于已知最薄弱环节。
